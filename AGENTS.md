# AGENTS.md — Provider Gateway for Claude (PGC)

Оглавление для агентов (Claude Code читает этот файл сам, если нет `CLAUDE.md`; Codex — тоже).
Здесь только то, чего не видно из кода. Архитектуру не описываем: её показывает код, а
решения — `docs/adr/`.

## Где правда

- `docs/adr/` — принятые решения. Читать перед задачей, которая трогает больше одного модуля
  или контракт. Решение, которого там нет, сначала записать (ADR), потом менять код.
- `docs/kb/reports/claude-1p-3p.md` — как Claude Code и Claude Desktop ведут себя через шлюз
  (переменные, ключи 3p, контракт Messages API, что выключено в 3p). Читать перед правкой
  шлюза, окружения Claude Code или записи Desktop. `docs/kb/ollama-reference.md` — что уже
  решено в Ollama. Сначала искать готовое там и в коде, потом писать своё.
- `docs/knowledge/issues.md` — найденное вне задачи. Записать туда, а не чинить молча.
- `docs/work/README.md` — цикл задание → CHECK → OUTPUT для задач больше одной правки.
- `CHANGELOG.md` — что меняется для человека (раздел Unreleased).

## Проверки (все зелёные до коммита)

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets -j2 -- -D warnings
cargo test --workspace -j2
node tools/check_i18n.js
node tools/ui-shots.mjs --detect   # если менялось окно (crates/ctp-app/ui)
```

Не больше двух параллельных сборок или тестов (`-j2`). Вывод команды — доказательство в
отчёте; «должно работать» доказательством не считается.

## Правила владельца

- push, слияние в main, релиз и публикация — только по его команде. Коммиты — да.
- Не трогать обычный Claude Desktop (`%APPDATA%\Claude`, его процессы) и чужие процессы.
  PGC работает со своим профилем `%LOCALAPPDATA%\ClaudeProviderGateway`.
- Секреты не читать и не выводить: ключи провайдеров (Credential Manager), ключ подписи
  обновлений (`handoff/`, `%USERPROFILE%\.tauri`), токены. Нужен секрет — остановиться и спросить.
- Временные файлы — в `%TEMP%\agents`, удалять после. Скрипты — файлом, не `-c`/`-e`
  (хуки владельца блокируют их с обратными слешами).
- Ответы владельцу — по-русски, коротко, с тем, что не проверено.

## Как работать

- Сначала критерий готовности (что увижу, какой командой проверю), потом код.
- Исправление ошибки идёт с тестом, который без исправления падает. Проверить: временно
  вернуть ошибку — тест должен упасть.
- Найти существующую реализацию прежде чем писать новую; работающий код и контракты не
  переписывать без ADR.
- Готово, когда независимая проверка (свежий контекст: подагент, ревью другой моделью) не
  нашла проблем по CHECK, а не когда исполнитель сам сказал «готово».
- Пользовательский текст — на двух языках: `tr!("ru", "en")` в Rust, `ui/i18n.js` в окне.
- Окно — только на общей шкале `styles.css` (`--r-*`, `--fs-*`, кнопки 34 px) и по
  брендбуку владельца; смотреть результат снимками `tools/ui-shots.mjs`, а не код.

## Ловушки (каждая уже стоила ошибки)

- Тест, который зовёт `claude::detect`, находит **настоящий** установленный Claude: так тест
  однажды собрал 700 МБ копии в `crates/ctp-app/unused`. В тестах — только временные папки
  (`temp_dir`) и фальшивые версии Claude.
- Claude Code сам повторяет запрос без отвергнутого (беты, thinking, effort), сжимает
  разговор и т. д. только по формулировкам Anthropic (`prompt is too long: N tokens > M
  maximum`, `capability_rejected:`). Ошибки провайдера переводить в эти слова, свои не выдумывать.
- Claude Desktop выкидывает модели с именами не как у Claude — поэтому псевдонимы шлюза
  `claude-…`. `behavesAs` передаёт сессии Code окно, предел вывода и effort той модели.
- Claude запускается с подменённой `LOCALAPPDATA` (свой профиль). Настоящую видят только
  процессы копии Claude (`ruui::ENV_PRELUDE`); копия пишет себя в реестр — его чинит
  `repair_registry`.
- GNU `sed`: `\L`/`\U` в замене меняют регистр и бьют кириллицу. Многострочные правки — Edit
  или скрипт на Python, который пишет UTF-8.
- `http::HeaderValue` принимает байты выше ASCII: кириллица в заголовке не ошибка.
- Русская копия Claude сама не обновляется (`App is not installed`): версии ставит обычный.
