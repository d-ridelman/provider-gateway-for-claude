# AGENTS.md — Provider Gateway for Claude (PGC)

Оглавление для агентов (Claude Code читает этот файл сам, если нет `CLAUDE.md`; Codex — тоже).
Здесь только то, чего не видно из кода. Архитектуру не описываем: её показывает код, а
решения — `docs/adr/`.

## Где правда

- `docs/adr/` — принятые решения. Читать перед задачей, которая трогает больше одного модуля
  или контракт. Решение, которого там нет, сначала записать (ADR), потом менять код.
- `notes/` — локальные заметки владельца, в git не попадают (`.gitignore`); нет папки —
  работать без неё:
  - `notes/kb/reports/claude-1p-3p.md` — как Claude Code и Claude Desktop ведут себя через
    шлюз (переменные, ключи 3p, контракт Messages API, что выключено в 3p). Читать перед
    правкой шлюза, окружения Claude Code или записи Desktop. `notes/kb/ollama-reference.md` —
    что уже решено в Ollama. Сначала искать готовое там и в коде, потом писать своё.
  - `notes/knowledge/issues.md` — найденное вне задачи и не проверенное вживую. Записать
    туда, а не чинить молча.
  - `notes/work/README.md` — цикл задание → CHECK → OUTPUT для задач больше одной правки.
- `CHANGELOG.md` — что меняется для человека (раздел Unreleased).
- Правила по частям: `.claude/rules/gateway.md` (шлюз), `.claude/rules/ui.md` (окно) —
  Claude Code грузит их сам по путям, остальным агентам читать при правке этих частей.

## Проверки (все зелёные до коммита)

```powershell
.\tools\ci.ps1                     # переводы, fmt, clippy, тесты; первая ошибка — стоп
node tools/ui-shots.mjs --detect   # если менялось окно; нужен плагин impeccable, вывод без находок
```

Тот же `tools/ci.ps1` запускают хук `pre-push` (`.githooks/`, включается
`git config core.hooksPath .githooks`) и GitHub CI. Локально скрипт ставит 2 задания сборки;
одновременно — не больше двух сборок или прогонов тестов. Вывод команды — доказательство в
отчёте; «должно работать» доказательством не считается.

## Правила владельца

- push, слияние в main, релиз и публикация — только по его команде. Коммиты — да.
- Репозиторий публичный: в него — только код и документация для людей. Заметки, разборы,
  личные пути, имена провайдеров владельца, снятое из декомпилята Claude — в `notes/`.
- Не трогать обычный Claude Desktop (`%APPDATA%\Claude`, его процессы) и чужие процессы.
  У PGC свой профиль: `%LOCALAPPDATA%\ClaudeProviderGateway` (dev-сборка —
  `ClaudeProviderGateway-dev`, при `CLAUDE_GATEWAY_HOME` — `<home>\claude`).
- Секреты не читать и не выводить: ключи провайдеров (Credential Manager), ключ подписи
  обновлений (вне репозитория), токены. Нужен секрет — остановиться и спросить.
- Временные файлы — в `%TEMP%\agents`, удалять после. Скрипты — файлом, не `-c`/`-e`
  (хуки владельца блокируют их с обратными слешами).
- Ответы владельцу — по-русски, коротко, с тем, что не проверено.

## Как работать

- Сначала критерий готовности (что увижу, какой командой проверю), потом код.
- Исправление ошибки идёт с тестом, который без исправления падает. Проверить: временно
  вернуть ошибку — тест должен упасть.
- Найти существующую реализацию прежде чем писать новую; работающий код и контракты не
  переписывать без ADR.
- Готово, когда независимая проверка (свежий контекст: подагент, ревью другой моделью) не
  нашла проблем по CHECK, а не когда исполнитель сам сказал «готово». С плагином agent-kit —
  `agent-kit critic` и `agent-kit verify` (ADR-013), иначе подагент и `tools/ci.ps1`.
- Пользовательский текст — на двух языках: `tr!("ru", "en")` в Rust,
  `crates/ctp-app/ui/i18n.js` в окне.

## Ловушки (каждая уже стоила ошибки)

- Тест не должен собирать копию Claude и писать в настоящую установку: `claude::detect`
  находит **настоящий** Claude, и тест однажды собрал 700 МБ копии в
  `crates/ctp-app/unused`. Для сборок — `temp_dir` и фальшивые версии Claude; читать
  настоящую установку можно.
- Claude Code сам повторяет запрос без отвергнутого и сжимает разговор только по
  формулировкам Anthropic (ADR-003). Ошибки провайдера переводить в эти слова, свои не выдумывать.
- Имена моделей для Desktop — только через `crates/ctp-core/src/alias.rs` (ADR-005): он же обходит
  фильтр Desktop по словам в имени.
- `LOCALAPPDATA` у Claude подменена (ADR-001); настоящую процессам возвращает только копия
  (ADR-002), и не всем (`utilityProcess`).
- GNU `sed`: `\L`/`\U` в замене меняют регистр и бьют кириллицу. Многострочные правки — Edit
  или скрипт на Python, который пишет UTF-8.
- `http::HeaderValue` принимает байты выше ASCII: кириллица в заголовке не ошибка.
- Шелл агента задаёт `NO_COLOR=1`. PGC, запущенный из него (и установщиком `/S`, которого
  запустил агент), отдаёт его консоли «Claude Code» и Claude Desktop — консоль без цвета.
  PGC запускать через `explorer.exe "<путь>"`, установщик — после `Remove-Item Env:NO_COLOR`
  в том же PowerShell (он сам запускает PGC и передаёт ему своё окружение).
- Встроенный agent-kit — снимок коммита из `crates/ctp-app/kit.pin` (`tools/kit-snapshot.ps1`).
  Новый agent-kit закреплять только после того, как точные вызовы PGC (`inspect`, `setup --json`,
  `--propose`, `--apply --only --checks`, всё с `--lang`) прошли на распакованном снимке: agent-kit
  отвергает незнакомые флаги кодом 2. `--apply` с кодом 1 и `failed` — ответ, а не сбой.
- Случаи «Подключить проект» — таблица ADR-014; у каждой строки тест `case_NN_…`, тест-сторож
  падает, если строки без теста. Новый случай — сначала строка, потом тест и код.
- Живая проверка страницы проекта — во временном репозитории в `%TEMP%\agents`, не в проектах
  владельца: «Подключить» ставит плагин и пишет `.claude/settings.local.json` в выбранную папку.
