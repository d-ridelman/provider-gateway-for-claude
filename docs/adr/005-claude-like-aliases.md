# ADR-005. Псевдонимы моделей claude-… и behavesAs для effort

- Status: Accepted
- Date: 2026-11-19 (записано 2026-11-24)

## Context
Claude Desktop (с ~1.6259) выкидывает из списка модели, чьи имена не похожи на Claude.
Уровни рассуждения (effort) Desktop показывает только у модели, которую узнаёт.

## Decision
Шлюз выдаёт модели под псевдонимами `claude-<провайдер>-<8 цифр из хеша>`
(`ctp-core/src/alias.rs`). Desktop отбрасывает и имя с `claude-`, если в нём есть слово из
его списка: тогда псевдоним запасной, `claude-p<6 цифр>-<8 цифр>`. Моделям не Claude с
потолком effort (OpenAI и Anthropic-совместимые: DeepSeek, GLM…) Desktop получает
`behavesAs: "claude-opus-4-8"` (`claude::EFFORT_PROFILE`, окно 1M), моделям Claude — их
собственный ID. Окно модели неизвестно — считаем 1M (так же консоль, `code_env`): заниженное
окно хуже завышенного (см. Consequences).
Консоль Claude Code фильтра имён не имеет и подписывает заголовок самим ID, поэтому
получает настоящий ID модели (шлюз его понимает), как `ollama launch claude`; псевдоним —
только если тот же ID есть у двух моделей шлюза.

## Consequences
- Модели видны и в Desktop, и в Claude Code; уровни effort работают.
- `behavesAs` передаёт сессиям Code ещё и окно образца (1M). Модель с меньшим окном сжимается
  позже нужного — это прикрывает перевод переполнения в «prompt is too long» (ADR-003).
- Попытка ставить моделям без `[1m]` образец с окном 200K (`claude-opus-4-6`, коммит
  `40dc8aa`) вживую дала бесконечное сжатие: 626 инструментов MCP заняли 180K из 200K, сжимать
  было нечего. Отменена; 200K допустимо только при окне, известном из каталога.

Исправление от 25.11: «образец с окном 200K» — это то, как вёл себя Desktop вживую, а не окно
самой модели. По каталогу моделей Anthropic (справочник Claude API, снимок 03.11.2026) у Opus 4.6
окно 1M. Почему Desktop считал 200K, не разобрано.
