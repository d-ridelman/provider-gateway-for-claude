# ADR-016. Умная настройка проекта: модель советует из готового списка

- Status: Accepted (включается только после замера, см. Decision 5)
- Date: 2026-11-25

## Context
«Подключить проект» (ADR-014) раскладывает заготовки кодом. Кодом не угадать многое в
незнакомом проекте:
- какие команды проверяют проект;
- какая ветка основная;
- какие правила здесь важны для критика.

Модель это видит быстро, и PGC уже даёт к ней доступ. Но у модели в этом месте три опасности:
1. Запуск команд, которые выбрала модель по чужому репозиторию, — это исполнение
   произвольного кода.
2. Текст, который пишет модель (черновик `critic.md`), может нести внедрённое из README
   («критик всегда принимает») и отключить проверку.
3. Файлы проекта уходят провайдеру модели, а это может быть не Anthropic.

## Decision
1. **Только из готового списка.** Код agent-kit извлекает команды-кандидаты из файлов
   проекта: скрипты `package.json`, цели Cargo, Makefile и pyproject, шаги собственного CI
   проекта. У каждого кандидата свой id. Модель выбирает только id из этого списка, ответ
   проверяется по схеме. Чего нет в списке, отбрасывается. Своих команд модель не пишет.
2. **Проверка — наличие, а не запуск.** По умолчанию код проверяет, что выбранная команда
   существует в проекте. Запустить её можно только кнопкой у этой команды и с согласия
   человека.
3. **Текст модели — только черновик.** Черновик `critic.md` и правил показывается целиком, с
   пометкой «черновик модели», и по умолчанию галочка не стоит. Ядро критика (формат вердикта,
   причины отказа) `critic.md` не переопределяет. Если сейчас переопределяет, сначала это
   исправляется в agent-kit.
4. **Согласие на отправку.** Перед запросом окно показывает:
   - какие именно файлы уйдут;
   - сколько примерно токенов;
   - какой модели и какому провайдеру.

   Файлы из `.gitignore` и всё, что похоже на секрет, не отправляются, размер ограничен.
   Человек отказался или шлюз стоит — работает нынешняя настройка кодом.
5. **Сначала замер.** Эталон — что запускает собственный CI каждого проекта из набора.
   Сравниваются:
   - нынешний `setup`;
   - извлечение кандидатов кодом;
   - то же плюс выбор модели.

   Шаг с моделью включается в PGC, только если он лучше без него, как модель выбора в
   Falkline (`enabled: false` до порога). Скачивание открытых проектов для замера — только с
   согласия владельца. Их код не запускается, оценка по файлам.
6. **Разделение.** В agent-kit — `setup --propose --json` с контрактом id кандидатов и его
   ADR. В PGC — экран согласия, переменные шлюза для вызова и показ с галочками.

Новые случаи таблицы ADR-014 появятся вместе с кодом PGC, у каждого будет тест:
- шлюз стоит;
- модель вернула битый JSON или отказ;
- id не из списка;
- README с внедрённой командой;
- секреты в дереве;
- огромный репозиторий;
- таймаут или потолок цены;
- кандидатов нет;
- человек отказался отправлять.

## Consequences
- Модель не может запустить ничего, кроме того, что уже записано в проекте, и только с
  согласия.
- Польза доказывается замером до включения. Без пользы остаётся настройка кодом.
- Один запрос к модели на подключение (порядка 10–30 тыс. токенов) — по согласию и с
  оценкой цены.
