# ADR-012. Модель-критик для скриптов

- Status: Accepted
- Date: 2026-11-25

## Context
Критик проекта (например, из agent-kit) запускает `claude -p` на другой модели, чем модель,
которая сделала работу, и проверяет её. С подпиской Claude он ходит в Anthropic. Человеку без
подписки нужна сторонняя модель через шлюз. agent-kit берёт путь через PGC из трёх
переменных: `AGENT_KIT_PGC_URL` (адрес шлюза), `AGENT_KIT_PGC_TOKEN` (его токен) и
`AGENT_KIT_PGC_MODEL` (модель). Ни одна из них не начинается с `ANTHROPIC_` или `CLAUDE_`,
так что критик не теряет их, когда чистит окружение. Скрипт сам не знает, какие модели есть
в PGC и на каком порту шлюз.

## Decision
В настройках PGC, рядом с основной моделью, есть выбор «модель-критик». Это модель шлюза,
она хранится как провайдер и ID, как основная (`ModelRoles.critic`). Если она выбрана и шлюз
работает, PGC задаёт три переменные `AGENT_KIT_PGC_*` и `AGENT_KIT_CRITIC_VIA=pgc` процессам,
которые запускает сам. Без последней критик выбирал бы путь сам по наличию файла входа в
Claude, а тот мог остаться от старого входа, и тогда критик ушёл бы в Claude без подписки.
Выбор модели-критика в PGC и есть решение идти через шлюз. Переменные получают:
Claude Desktop (их получают все сессии вкладки Code) и консоли Claude Code. Модель
передаётся тем же именем, что у консоли: ID модели, если он в шлюзе один, иначе псевдоним.
Смена критика шлюз не перезапускает: он нужен только скриптам. Файлов и переменных Windows
PGC для этого не пишет.

## Consequences
- Критик в проекте, открытом из Claude через PGC, без настройки идёт через выбранную модель,
  если подписки нет или так выбрано в самом критике.
- Скрипт, запущенный не из процесса PGC (обычный терминал), этих переменных не видит.
- Открытый Claude получает новую модель-критика после перезапуска, консоль — новую консоль.
- Токен шлюза уходит в окружение процессов, которые и так ходят в шлюз с этим токеном.
