# ADR-015. agent-kit приезжает внутри PGC

- Status: Accepted
- Date: 2026-11-25

## Context
Кнопка «Подключить проект» (ADR-014) ставит agent-kit из маркетплейса. У людей его нет: он
лежит только в папке владельца. Владелец решил, что agent-kit должен приезжать внутри
установщика PGC, а не отдельной публикацией.

У PGC две поставки: установщик NSIS и портативный exe. У портативного нет папки ресурсов,
поэтому agent-kit встраивается прямо в exe.

Проверено в отдельной `CLAUDE_CONFIG_DIR`:
- Плагин из папки без `.git` и без поля `version` получает версию `unknown`. `plugin update`
  перечитывает файлы, но устаревшую копию по версии не отличить.
- С полем `version` в `plugin.json` обновление идёт как положено: новая папка кэша и сообщение
  «updated from A to B».
- `claude plugin marketplace list --json` отдаёт `path` маркетплейса.

## Decision
1. **Закрепление версии.** В репозитории PGC лежит `crates/ctp-app/kit.pin` — коммит
   agent-kit. Исходников agent-kit в репозитории PGC нет.
2. **Снимок.** `tools/kit-snapshot.ps1` делает `git archive` закреплённого коммита из папки
   agent-kit (по умолчанию `..\agent-kit`). В снимок идут только части, нужные для работы:
   `.claude-plugin`, `bin` (команда `agent-kit`), `hooks`, `scripts`, `skills`, `templates`,
   `agents` и `LICENSE`. В
   `plugin.json` ставится `"version"` — первые 12 знаков коммита. Снимок —
   `crates/ctp-app/kit/agent-kit.tar`, его нет в git. `build.rs` встраивает его в exe. Если
   файла нет (GitHub CI, чужая машина), PGC собирается без agent-kit, и страница говорит, что
   встроенного нет.
3. **Защита релиза.** `tools/release.ps1` отказывается собирать релиз без снимка или со
   снимком другого коммита.
4. **Распаковка.** Распаковывается в постоянную папку
   `%LOCALAPPDATA%\ClaudeProviderGateway\agent-kit`, а не в папку с версией в имени: так
   источник маркетплейса не меняется от версии к версии. Если версия в метке `.pgc-kit` не
   совпадает со встроенной или в папке нет `.claude-plugin/plugin.json`, папка заменяется
   через временную. Сессии работают из кэша
   плагина, а не из этой папки, так что замена их не ломает.
5. **Маркетплейс.**
   - Не зарегистрирован — PGC регистрирует свою папку. Если источник задан в настройках PGC
     вручную, берётся он: его выбрали нарочно.
   - Зарегистрирован на папку PGC — PGC им управляет.
   - Зарегистрирован на другую папку (живая папка разработчика) — PGC его не трогает и
     ставит из него.
6. **Обновление только с согласия.** Если встроенная версия отличается от установленной копии
   проекта, страница говорит «другая версия» и показывает кнопку. Это хэши коммитов, порядка у
   них нет, поэтому «новее» не утверждается. Тихого обновления нет.
7. **Node.** Node 22 или новее по-прежнему нужен на машине: код agent-kit на Node.

## Consequences
- Люди получают agent-kit вместе с PGC, без публикации agent-kit отдельно. Его код при этом
  публичен внутри установщика, поэтому тексты нейтральные и есть лицензия.
- Обновление PGC привозит новый agent-kit, а в проект он попадает по кнопке.
- Сборка релиза требует папку agent-kit на машине сборщика.

Решение владельца от 25.11: отдельного публичного репозитория у agent-kit нет, он выходит только
внутри PGC. Его исходники — в самом установщике и переносном exe (снимок нужных для работы
частей, MIT) и в `%LOCALAPPDATA%\ClaudeProviderGateway\agent-kit` после распаковки. Пересобрать
релиз с тем же agent-kit может только тот, у кого есть клон с закреплённым коммитом; README
говорит об этом в «Сборке из исходников».
