# ADR-010. Модель шлюза не остаётся в настройках Claude Code

- Status: Accepted
- Date: 2026-11-25
- Supersedes: часть ADR-004 («PGC не пишет в настройки Claude Code»)

## Context
Консоль Claude Code из PGC берёт модель из переменных (`ANTHROPIC_MODEL` и роли), как
`ollama launch claude` берёт её из флага `--model`. Но команда `/model` с Enter в
интерактивной сессии Claude Code 2.1.331 всегда пишет выбор в общие настройки
пользователя (`settings.json` в `CLAUDE_CONFIG_DIR` или `%USERPROFILE%\.claude`) как модель
по умолчанию для новых сессий. Ни флаг, ни переменные этого не отменяют. Ollama этот
файл не трогает, и у неё та же утечка. В консолях PGC запись не видна, потому что
переменная сильнее файла. Но обычный `claude` без PGC открывается на модели вроде
`glm-5.3`, а у Anthropic такой модели нет, и Claude Code предупреждает «isn't recognized».

## Decision
PGC правит в этом файле только ключ `model` и только когда в нём модель шлюза:
- Моделью шлюза считается псевдоним PGC (`claude-<провайдер>-NNNNNNNN`) или ID модели
  провайдера из PGC, без `[1m]` и без учёта регистра. Исключение — ID, которые начинаются
  с `claude-`: они работают и у Anthropic напрямую. Псевдонимы Claude Code (`opus`,
  `sonnet` и прочие) тоже не трогаются.
- При запуске консоли (не портативной) PGC запоминает текущее значение `model` (или что
  его нет), если это не модель шлюза. Модель шлюза запомненное не затирает. Запомненное
  лежит в одном месте для всех сборок PGC (`%LOCALAPPDATA%\ClaudeProviderGateway`), потому
  что `settings.json` у них общий. Изолированный запуск (`CLAUDE_GATEWAY_HOME`) настоящие
  настройки не трогает.
- При старте и при выходе PGC, если в файле модель шлюза, он возвращает запомненное
  значение, а если его нет, убирает ключ. Запомненное стирается только после возврата:
  консоль PGC может пережить сам PGC.
- Если в том же `settings.json` есть `env.ANTHROPIC_BASE_URL`, обычный `claude` ходит к своему
  адресу человека, и `model` там его: PGC его не трогает (исправление от 25.11, по ревью).
- Файл, который не читается или не является JSON-объектом, PGC не трогает. Порядок и
  значения остальных ключей сохраняются; запись через временный файл (по ссылке — прямо).

## Consequences
- После выхода из PGC обычный `claude` открывается на прежней модели, а не на модели шлюза.
- Пока PGC работает, обычный `claude` ещё видит модель шлюза, если её выбрали через
  `/model`. PGC правит файл только при своём старте и выходе, а не на ходу: не проверено,
  как открытая консоль переживёт смену файла.
- Если человек сам поставил в общие настройки ID модели провайдера, например `glm-5.3`,
  PGC при старте или выходе её уберёт, если в файле нет своего `env.ANTHROPIC_BASE_URL`: без
  шлюза эта модель всё равно не работает.
- Портативный Claude Code держит настройки в папке PGC, его это не касается.
- Если модель или провайдера удалили из PGC раньше, чем PGC вышел, утёкшую модель он уже
  не узнает и оставит. Если у провайдера есть модель с именем псевдонима Claude Code
  (`opus`), PGC сочтёт такой псевдоним моделью шлюза.
