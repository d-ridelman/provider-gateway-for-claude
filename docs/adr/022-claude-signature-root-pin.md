# ADR-022. Подпись скачиваемого Claude: CN и отпечаток удостоверяющего центра

- Status: Accepted
- Date: 2026-11-26
- Supersedes: —

## Context

PGC скачивает исполняемые файлы Claude и запускает их: `Claude-Setup.exe`
(`claude.ai/api/desktop/…/setup/latest/redirect`) и портативный `claude.exe` из nupkg
(`downloads.claude.ai/releases/win32/…`). Перед запуском оба проверялись `WinVerifyTrust`
(Authenticode) и сравнением CN подписанта с `Anthropic, PBC` (`download.rs`).

Этого мало. `WinVerifyTrust` доверяет цепочке через хранилище пользователя, поэтому
сертификат, выпущенный корпоративным MITM-корнем (типичная настройка на доменных ноутбуках
за прокси), проверку проходит: нужен только CN `Anthropic, PBC`. Отзыв не проверялся
(`WTD_REVOKE_NONE`), хеш портативного пакета берётся из того же `RELEASES`, что и ссылка, —
это проверка целостности скачивания, а не подлинности. Сценарий проекта — как раз рабочий
ПК с прокси, так что это не отвлечённый риск.

Что подписывает Claude сегодня (проверено 26.11.2026 на портативном 7.37095.0 и на пакете
6.28899.6.0 — подпись одна и та же):

- листовой сертификат: CN `Anthropic, PBC` (O, L, штат Делавэр, номер 4860621),
  отпечаток SHA-1 `60C2D9C51F09822FFF4F194DE9EEDB67451292D1`, действует
  08.10.2026–29.10.2027, RSA 4096;
- выпустивший его центр: `DigiCert Trusted G4 Code Signing RSA4096 SHA384 2021 CA1`
  (`7B0F360B775F76C94A12CA48445AA2D2A875701C`);
- дальше цепочка `WinVerifyTrust` идёт через промежуточный `A99D5B79…` к
  `Microsoft Code Verification Root` (`0563B8630D62D75ABBC8AB1E4BDFB5A899B24D43`) —
  это перекрёстно подписанная ветка. Самодписанный `DigiCert Trusted Root G4`
  (`DDFB16CD…`), который показывает `Get-AuthenticodeSignature`, в цепочке провайдера
  не появляется.

## Decision

1. `ensure_anthropic` требует и CN `Anthropic, PBC`, и чтобы листовой сертификат был
   выпущен центром Anthropic — `7B0F360B…` (DigiCert Trusted G4 Code Signing … 2021 CA1).
   Отпечаток берётся из цепочки, которую проверил сам `WinVerifyTrust` (второй элемент —
   выпустивший сертификат), а не из отдельного разбора файла.
2. Закрепляем **выпускающий центр**, а не лист и не корень. Лист перевыпускается каждый
   год, и закрепление листа ломало бы установку у всех без выпуска PGC. Корень не годится:
   `WinVerifyTrust` на этой машине приходит к корню Microsoft, а самодписанный корень
   DigiCert в цепочке отсутствует; корень Microsoft общий для всех перекрёстно подписанных
   продуктов и Anthropic не выделяет. Центр DigiCert у Anthropic один и тот же у пакета и
   у портативного Claude, а корпоративный MITM-прокси выпускает сертификат своим корнем —
   такой центр в цепочку не попадёт.
3. Отзыв — по возможности: сначала `WTD_REVOKE_WHOLECHAIN`; если единственная причина
   отказа — «отзыв не проверить» (`0x80092013` — CRL/OCSP недоступны, `0x800B010E` — цепочка
   без отзыва), повторяем без проверки отзыва и продолжаем. Иначе установка Claude ломалась
   бы за прокси, который закрывает OCSP, — то есть ровно там, где PGC нужен. Отозванный
   сертификат (`0x80092010`) отвергается всегда.
4. Хеш портативного пакета (`RELEASES`) остаётся проверкой целостности; подлинность —
   подпись `claude.exe` после распаковки (уже есть, `installs.rs`).
5. Если Anthropic сменит удостоверяющий центр, обновление Claude остановится с сообщением,
   каким центром выпущен сертификат. Новый отпечаток добавляется выпуском PGC — это
   осознанная плата за то, что проверка не обходится установкой своего корня.

## Consequences

- Подмена скачиваемого Claude сертификатом от корпоративного прокси больше не проходит;
  диагностика отличает «не Anthropic» (CN) от «цепочка не к тому корню» (отпечаток).
- Установка и обновление Claude требуют, чтобы цепочка доходила до корня DigiCert в
  хранилище; это стандартное состояние Windows.
- Не делаем: закрепление листового сертификата или его ключа (ломается на перевыпуске),
  проверку отпечатка самих файлов (кроме уже проверяемого sha1 из `RELEASES`), свой список
  доверенных корней.

## Проверки

- `download::signer` на подписанном файле возвращает CN и отпечаток выпустившего центра;
  на файле без подписи — ошибку.
- `check_anthropic` отвергает подпись с другим CN и сертификат другого центра (табличный
  тест без вызовов Windows).
- Живой тест `installed_claude_is_signed_by_anthropic` на установленном Claude (на машине
  без Claude ничего не проверяет).
- Вручную 26.11.2026: отпечатки листа, промежуточного и корня сняты `Get-AuthenticodeSignature`
  с портативного 7.37095.0 и из пакета 6.28899.6.0 — совпали.
